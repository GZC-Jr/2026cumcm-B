# 问题三技术核对

本文件把 `docs/问题三求解思路.md` 中的公式、`code/t3/t3.py` 中的实现和可验证范围对应起来。安全条件与排序代理分开：前者用于保证不误判，后者只用于决定下一动作。

## 已验证的不变量

`code/t3/verify_t3.py` 会写入指定的 `outputs/t3/<audit_name>/verification_results.json`，并验证：

1. 五个环形布局的解析覆盖证书和不可行布局拒绝；
2. 1000 m 接收边界以及环形扇区两个端点；
3. 带有 $[-1,1]$ 度误差的合成交会观测不会把真实点裁出保守多边形；
4. MEC 覆盖、直径下界和 Jung 上界；
5. 失败清除后旧 `planned` 和 `probe_base` 不会继续使用，条件后验不在失败圆内；
6. 一个 `LocalBackend` 全流程案例的清除完成、虚拟时间守恒和状态记录；
7. 已发现频道收到后续 `no_signal` 时，存在性保持为1、硬定位多边形不变、规划后验更新且旧计划失效；
8. 空/退化区域、空测站、窄多边形、严格接收裕量、优化器异常返回和后验权重退化的回归检查。
9. `/enter` 返回的现实剩余时间和虚拟上限必须为有限合法值；非法 `NaN`、无穷、负值、非整数或超范围值不会污染本地时钟与截止预算。
10. `direction` 响应的 `svd_deg` 必须为有限且位于 `[0,360)` 的数值；非法角度或时间戳不会推进本地动作计数。

验证脚本不访问官方接口；因此不能替代正式测试，也不能产生正式案例编码或加密行为日志。

## 边界语义与权限层级

为避免数值近边界时把“不可证明”误当成“可接收”或“已清除”，当前实现固定采用以下语义：

1. `reception_upper_bound_m2` 在三角形顶点上计算保守的平方距离上界，`reception_certified` 要求上界不大于 `-RECEIVE_MARGIN_M2`；因此恰好等于 1000 m 的候选不会因为浮点容差被接受。所有补测入口共用这一判定。
2. 空区域、单点、线段、共线多边形或空三角形网格均不视为“可接收”。规划器返回退化原因并转入 25 m 网格兜底；若兜底也没有可行点，则安全停止并记录未完成状态，而不是伪造清除成功。
3. 高斯后验、信息增益、DOP 和试探概率只用于行动排序与成本估计。它们不改变硬定位外包区域，也不产生完成证明；几何证书以及模拟器返回的实际 `clear_result` 拥有最终权限。任何失败清除都会撤销旧计划并使相关缓存失效。

`code/t3/verify_t3.py` 已加入这些边界回归：退化区域、空测站集合、窄多边形、1000 m 严格边界、SLSQP 异常/失败/非有限返回、后验权重退化、失败反馈失效链路、`/enter` 时间预算非法值、`direction` 角度和时间戳非法值，以及直接调用 `depth_weighted_dop`/`joint_probe_plan` 时的非法坐标、负半径和非有限前瞻防护。当前共 17 项检查。

最近一次加固验证命令为：

```text
python -m py_compile code/t3/t3.py code/t3/verify_t3.py
python code/t3/verify_t3.py --output outputs/t3/verification_after_enter_guard
```

结果为 17/17 通过；报告写入 `outputs/t3/verification_after_protocol_guards/verification_results.json`。其中 `local_time_accounting` 仍是 LocalBackend 合成案例，`protocol_boundaries` 额外验证了 `/exit` 返回 0 不会回写掉已有虚拟时钟，`enter_budget_guards` 覆盖了 `NaN`、无穷、负值、非整数和超范围时间预算，`measure_response_guards` 覆盖了非法 `svd_deg` 与负/非有限虚拟时间，`official_simulator_test` 明确为 `false`。

## 风险与待定事项

| 事项 | 影响 | 当前处理 | 需要确认 |
| --- | --- | --- | --- |
| 默认布局 | 影响移动距离与扫描服务次数 | 当前为 `ring8_939`，其理论最坏距离约999.319 m | 正式测试前是否沿用，或先用共同随机数比较五种布局 |
| `search_gain` | 改变未知频道批量扫描顺序，不改变覆盖/完成保证 | 定义为 $H(\text{检测结果})+\text{search\_gain}\times P(\text{接收})$，默认0.2 | 是否按演练日志调参，及是否保持该定义 |
| `lookahead` | 改变试探计划对后续路程的惩罚 | 定义为后续尾程距离权重，默认1.0，范围0--1 | 是否保持1.0；它不是概率，也不是时间单位 |
| 概率后验 | 受求积网格、噪声尺度和固定半径先验影响 | 仅用于排序；几何外包和真实清除反馈拥有最终权限 | 论文中是否明确标注为规划近似而非统计保证 |
| DOP | 当前是截断/正则化的数值代理 | 只在主目标近优时作决胜，至少需2%改善 | 是否需要演练中单独记录 DOP 决胜频率和收益 |
| 兜底网格 | 极端窄区域或优化失败时保证继续尝试，但可能增加清除失败次数 | 25 m 网格按蛇形顺序，失败结果不会被当成成功 | 是否接受极端案例的时间代价，还是把更多计算预算给候选优化 |
| 官方测试 | 真实目标数、案例编码和加密日志不在代码可见范围 | 只保留本地合成结果，并在输出中显式标记非官方 | 需要在模拟器登录后提供队号、三次案例编码及导出日志 |

当前 `outputs/t3/` 中的数值结果全部来自 `LocalBackend` 的本地合成案例或确定性证书检查，不能当作官方模拟器成绩。官方模拟器尚未连接，因此目前没有正式案例编码、正式统计值或加密行为日志；这些字段须在模拟器侧完成三次正式测试后原样补入论文和支撑材料。

## 结论

硬几何条件、状态机、路径调度、反馈失效和计时记账已经在初版脚本中落地；后验、信息增益、DOP 和试探链路是可解释的排序近似。当前最重要的外部待办是用模拟器做演练并决定默认布局/参数，然后再进行三次正式测试，按题目要求保存原始日志文件名。
